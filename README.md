# Система бенчмаркинга скорости декомпозиции задач на базе локальных CPU-совместимых LLM

CLI-утилита для автоматизированного тестирования open-source языковых моделей, работающих исключительно на CPU. Программа последовательно загружает выбранные модели, отправляет фиксированный запрос, измеряет время генерации, валидирует структуру ответа и формирует отчет.

## Требования к оборудованию

- **CPU**: до 4 потоков
- **ОЗУ**: 4 ГБ минимум
- **Диск**: SSD/HDD с объемом свободной памяти не менее 3 ГБ
- **GPU**: не требуется (инференс только на CPU)

## Установка зависимостей

```bash
pip install -r requirements.txt
```

### Примечания по установке

Для `llama-cpp-python` рекомендуется установить переменные окружения перед установкой:

```bash
# Для CPU-only сборки (рекомендуется)
export CMAKE_ARGS="-DGGML_BLAS=OFF"
pip install llama-cpp-python --no-cache-dir
```

## Быстрый старт

### Вариант 1: Использование конфигурационного файла

1. Скопируйте пример конфигурации:
   ```bash
   cp config.example.yaml config.yaml
   ```

2. Отредактируйте `config.yaml`, указав пути к вашим GGUF-файлам:
   ```yaml
   models:
     - /path/to/qwen2.5-1.5b-instruct.Q4_K_M.gguf
     - /path/to/llama-3.2-3b-instruct.Q4_K_M.gguf
   ```

3. Запустите бенчмарк:
   ```bash
   python benchmark_runner.py --config config.yaml
   ```

### Вариант 2: Прямое указание моделей

```bash
python benchmark_runner.py \
    --models model1.gguf model2.gguf model3.gguf \
    --output ./results \
    --log-level INFO
```

## Параметры командной строки

| Параметр | Краткий | Описание |
|----------|---------|----------|
| `--config` | `-c` | Путь к файлу конфигурации (YAML/JSON) |
| `--models` | `-m` | Список путей к GGUF файлам |
| `--output` | `-o` | Директория для выходных файлов (по умолчанию: `./benchmark_output`) |
| `--log-level` | - | Уровень логирования: DEBUG, INFO, WARNING, ERROR |
| `--no-subprocess` | - | Запускать модели в текущем процессе (не рекомендуется для слабого железа) |

## Фиксированный запрос

Текст задачи строго ограничен: **"разработка и поддержка типового справочника в Atacama RDM"**

## Параметры генерации

- **Температура**: 0.2 (понижается до 0.1 при повторном прогоне)
- **Top P**: 0.85
- **Max Tokens**: 512
- **Контекстное окно**: 2048 токенов

## Процедура тестирования

1. **Warmup**: 1 прогон без замеров для "прогрева" модели
2. **Основные прогоны**: 3 итерации с измерением времени
3. **Валидация**: Проверка структуры JSON ответа
4. **Повторный прогон**: При нарушении формата JSON (максимум 1 повтор с температурой 0.1)
5. **Очистка памяти**: Выгрузка модели после завершения тестирования

## Схема ответа модели

Модель должна вернуть JSON следующей структуры:

```json
{
  "tasks": [
    {
      "id": 1,
      "title": "Заголовок задачи",
      "description": "Описание задачи",
      "dependencies": [],
      "priority": 3,
      "estimated_effort": 2.5
    }
  ]
}
```

### Поля задачи

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer | Уникальный целочисленный идентификатор |
| `title` | string | Краткий заголовок задачи |
| `description` | string | Подробное описание задачи |
| `dependencies` | array[int] | Массив ID зависимых задач |
| `priority` | integer | Приоритет от 1 (низкий) до 5 (высокий) |
| `estimated_effort` | number | Оценка усилий в часах |

## Выходные данные

### Формат отчетов

Программа генерирует два типа отчетов в директории вывода:

1. **JSON отчет** (`benchmark_results_YYYYMMDD_HHMMSS.json`):
   - Полные данные со всеми метриками
   - Сырые ответы моделей
   - Детальная информация о каждом прогоне

2. **CSV отчет** (`benchmark_results_YYYYMMDD_HHMMSS.csv`):
   - Табличный формат для анализа в Excel/LibreOffice
   - Сводные данные по моделям

### Структура JSON отчета

```json
{
  "benchmark_date": "2024-01-15T10:30:00",
  "fixed_prompt": "разработка и поддержка типового справочника в Atacama RDM",
  "parameters": {
    "temperature": 0.2,
    "top_p": 0.85,
    "max_tokens": 512,
    "context_window": 2048
  },
  "models": [
    {
      "model_name": "qwen2.5-1.5b-instruct.Q4_K_M",
      "quantization": "Q4_K_M",
      "status": "passed",
      "runs": [...],
      "summary": {
        "avg_time_sec": 12.5,
        "median_time_sec": 11.8,
        "success_rate": 1.0,
        "ram_peak_mb": 1024
      }
    }
  ]
}
```

### Статусы моделей

| Статус | Описание |
|--------|----------|
| `passed` | ≥80% валидных ответов |
| `degraded` | 50-79% валидных ответов |
| `failed` | <50% валидных ответов или ошибка загрузки |
| `timeout` | Превышение лимита времени (10 минут на модель) |

## Архитектурные особенности

### Изоляция процессов

Для предотвращения утечек памяти на слабом железе каждая модель запускается в изолированном subprocess с явным освобождением ресурсов после завершения.

### Измерение времени

- **Старт таймера**: момент отправки первого токена движку инференса
- **Стоп таймера**: момент получения завершающего токена
- Время загрузки модели и инициализации контекста **не учитывается**

### Обработка ошибок

- Ошибки загрузки GGUF обрабатываются без падения всего скрипта
- При нехватке ОЗУ тест для текущей модели прекращается
- Циклические зависимости в ответе фиксируются в логе

## Логирование

Логи сохраняются в директорию вывода с именем `benchmark_YYYYMMDD_HHMMSS.log`.

Формат записи:
```
2024-01-15 10:30:00 | INFO    | Загрузка модели: /path/to/model.gguf
2024-01-15 10:30:05 | INFO    | Прогон 1/3
2024-01-15 10:30:15 | INFO    |   Время: 10.234s | Статус: ✓ VALID
```

## Критические ограничения

1. **Скорость генерации**: Модели до 3B токенов на слабом CPU генерируют 2-8 токенов/сек. Ожидание ответа может занимать 15-40 секунд.

2. **Валидность JSON**: Без грамматических ограничений модели до 3B нарушают JSON-схему в 20-45% случаев.

3. **Потребление памяти**: Последовательная загрузка нескольких GGUF без явного освобождения памяти вызовет OOM на 4 ГБ RAM.

4. **Function Calling**: Не реализуется нативно. Это паттерн валидации и маршрутизации JSON.

## Troubleshooting

### Ошибка: "ERROR: llama-cpp-python not installed"

```bash
pip uninstall llama-cpp-python
CMAKE_ARGS="-DGGML_BLAS=OFF" pip install llama-cpp-python --no-cache-dir
```

### Ошибка: "Failed to load model"

Проверьте:
1. Путь к файлу указан верно
2. Файл имеет расширение `.gguf`
3. Достаточно свободной памяти (минимум 3 ГБ)

### OOM (Out of Memory)

Используйте флаг `--no-subprocess` только если уверены в достаточности памяти. По умолчанию используется изоляция процессов.

### Медленная генерация

Это ожидаемое поведение для CPU-инференса. Для ускорения:
- Используйте модели меньшего размера (1.5B вместо 3B)
- Применяйте квантизацию Q4_K_M
- Уменьшите `max_tokens` в конфигурации
